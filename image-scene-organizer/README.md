# Image Scene Organizer — 1차 프로토타입

이미지를 여러 **영역(Region)** 으로 나누고, 생성 순서와 상관없이 **사용자가 직접 최종 순서를 정하고**,
확정된 부분을 **잠그고**, 영역 단위로 **저장/재사용**하고, 마지막에 **실제 파일명을 순서대로 일괄 변경**하는
캔버스형 데스크톱 도구입니다.

> 생성은 아무 순서로, 정리는 원하는 순서로, 확정된 것은 보호하고, 전체 흐름은 한눈에.

---

## 1. 실행 방법

### Windows — 설치 없이 exe로 실행
GitHub Actions가 PR이 갱신될 때마다 Windows 서버에서 exe를 빌드하고, 그 exe로 자체 테스트(§33 핵심 흐름)를 돌립니다.
1. PR 페이지 → **Checks** 탭 → *Image Scene Organizer* 실행 → 아래쪽 **Artifacts**에서
   `ImageSceneOrganizer-windows` 내려받기 (GitHub 로그인 필요, 90일 보관)
2. 압축을 풀고 `ImageSceneOrganizer.exe` 실행 (Python 필요 없음)
   - 서명되지 않은 exe라서 SmartScreen 경고가 나오면 *추가 정보 → 실행*을 누르세요.
- 같은 화면의 `selftest-report-windows`에는 Windows에서 실제로 돌린 자체 테스트 결과(`report.txt`)와 화면 캡처가 들어 있습니다.
- 직접 확인: `ImageSceneOrganizer.exe --self-test=C:\temp\iso` → 결과가 `C:\temp\iso\report.txt`에 저장됩니다.

### Windows — 소스로 실행
1. Python 3.10 이상 설치 — <https://www.python.org/downloads/> (설치 화면에서 **"Add python.exe to PATH"** 체크)
2. `image-scene-organizer\run.bat` 더블클릭
   - 첫 실행 때만 `.venv` 폴더를 만들고 PySide6(약 200MB)를 설치합니다. 몇 분 걸립니다.
   - 그다음부터는 바로 실행됩니다.

### 직접 실행 (Windows / macOS / Linux)
```bash
cd image-scene-organizer
python -m pip install -r requirements.txt
python main.py                 # 빈 프로젝트
python main.py my.isproj       # 프로젝트 바로 열기
```

### 자동 테스트
```bash
python -m pip install -r requirements-dev.txt
python -m pytest tests
```
단위 테스트(순서/잠금/저장/이름변경/이동)와 실제 창에 마우스·키·휠 이벤트를 보내는 End-to-End 테스트
(§33 테스트 흐름 전체, 사이드바·검색·상태줄·드래그 연출·영역 안 스크롤·팁, 크래시 복구)가 포함되어 있고,
화면 테스트는 한국어와 영어로 각각 돌며 번역이 하나라도 빠지면 실패합니다. 화면 없이도 돌아갑니다(`QT_QPA_PLATFORM=offscreen`).
CI: `.github/workflows/image-scene-organizer.yml` (Windows 2종 + Linux 테스트, Windows exe 빌드 + 자체 테스트).

## 3. 기술 선택과 구조

**Python 3 + PySide6(Qt 6)** 를 골랐습니다.
- `QGraphicsView`: 수백~수천 개 항목의 확대/이동/선택이 빠르고, 화면에 보이는 것만 그립니다.
- 탐색기 드래그&드롭, 휴지통 삭제(`QFile.moveToTrash`), 실제 파일 이름 변경을 기본 기능으로 쓸 수 있습니다.
- 설치는 `pip install PySide6` 한 줄이고, 나중에 PyInstaller로 단일 exe로 묶을 수 있습니다.

```
image-scene-organizer/
  main.py, run.bat
  scene_organizer/
    model.py      데이터 모델 · 순서/잠금 규칙 · 저장 형식 (Qt 없음, 단위 테스트 대상)
    fileops.py    실제 파일 작업만 여기서: 폴더 스캔, 일괄 이름변경(미리보기/롤백/로그), 휴지통, 탐색기 열기
    thumbs.py     백그라운드 썸네일 생성 + 디스크/메모리 캐시
    items.py      영역/썸네일 그리기
    canvas.py     캔버스 상호작용 (줌, 패닝, 선택 박스, 드래그 삽입, 우클릭 취소, 파일 드롭)
    viewer.py     크게 보기 창
    dialogs.py    일괄 이름변경 미리보기, 환경설정
    mainwindow.py 메뉴/툴바/명령/Undo/클립보드/저장/자동저장
    selftest.py   exe 자체 테스트 (--self-test=폴더)
    i18n.py       UI 언어 (한국어 기본 / English), 번역 표
    sidebar.py    왼쪽 사이드바 (캔버스 미리보기, 영역 목록, 팁)
    theme.py      밝은/어두운 테마, 글꼴
    icons.py      아이콘 (assets/icons, Lucide)
    tips.py       팁 문구와 움직이는 그림 안내 창
    assets/       아이콘(Lucide, ISC 라이선스), 글꼴(Pretendard, SIL OFL 1.1) — 라이선스 파일 포함
  tests/
```

- **모델이 유일한 원본**이고 캔버스는 그것을 비추기만 합니다. 정리 작업(순서, 이동, 복사, 잠금)은
  `model.py`만 바꾸고, 디스크를 건드리는 코드는 전부 `fileops.py`에 있습니다(§27 분리).
- **Undo/Redo**는 변경 직전 프로젝트 상태를 통째로 저장하는 방식입니다(최대 150단계). 이미지 1000장
  기준 저장 약 1ms, 복원 약 15ms로 측정됐습니다.
- **저장 형식**: JSON. 프로젝트 `.isproj`, 영역 `.isregion`. 이미지 경로는 절대경로와
  파일 위치 기준 상대경로를 함께 저장해서, 프로젝트와 이미지 폴더를 같이 옮겨도 다시 찾습니다.

## 4. 완성 점검표

상태: **완료** = 구현했고 근거(테스트·확인)가 있음 · **미완료** = 하지 않음 · **결정 필요** = 사용자가 정할 일.
근거의 `test_…`는 `tests/` 안의 자동 테스트 이름입니다(한국어·영어로 각각 실행). "Windows 자체 테스트"는 CI에서
빌드한 exe를 Windows 서버에서 직접 실행한 결과입니다.

## 7. 만들면서 발견한 UX 충돌과 개선 제안

1. **잠금 + 자동 정렬 규칙** (가장 중요).
   두 가지 방식이 있었습니다. (a) 잠긴 이미지가 *칸 번호*에 고정되고 나머지가 그 주위로 흐르는 방식, (b) 잠긴 이미지들이
   *묶음 순서*를 지키는 방식. (a)는 잠기지 않은 이미지가 잠긴 이미지를 넘어 앞뒤가 바뀌는 일이 생겨서 "사용자가 정한
   순서를 프로그램이 바꾸지 않는다"(§1-2)는 원칙과 충돌합니다. 그래서 **(b)** 로 만들었습니다.
   - 잠긴 묶음은 쪼갤 수 없고, 묶음 안에 놓으면 묶음 바로 뒤에 들어갑니다.
   - 영역 맨 앞의 잠긴 묶음은 맨 앞에 고정됩니다. 1–5를 잠그면 0번 자리에 놓아도 6번이 됩니다.
   - 가운데 있는 잠긴 묶음 *바로 앞*에는 넣을 수 있습니다. 묶음 전체가 한 칸씩 밀리지만 내부 순서는 그대로입니다.
     이게 어색하면 `adjust_insert_index`의 한 줄만 바꾸면 됩니다.
2. **영역 너비가 픽셀 단위**라서 썸네일을 키우면 한 줄에 들어가는 개수가 줄고, 이미지가 많은 영역은 세로로 긴 띠가
   됩니다(1000장 테스트에서 확인). 너비를 "열 개수"로 저장하는 쪽이 나을 수 있습니다. 써 보시고 결정해 주세요.
3. **이미지를 클릭하면 그 영역이 활성 영역**이 됩니다. 그래서 다음 가져오기가 그 영역으로 갑니다. 대부분은 원하는
   동작이지만, 다른 영역을 보다가 가져오면 의외일 수 있습니다. 가져온 뒤 상태줄에 대상 영역과 위치를 표시합니다.
4. **Ctrl의 의미가 여러 개**입니다: Ctrl+클릭(선택 토글), Ctrl+드롭(복사), 제목줄 Ctrl+클릭(영역 다중 선택),
   Ctrl+휠(썸네일 크기). 서로 겹치지는 않지만, 바꾸고 싶은 키가 있으면 알려 주세요.
5. **같은 파일이 여러 영역에 복사되어 있을 때 일괄 이름 변경**을 하면, 다른 영역에 있는 같은 이미지의 파일 이름도
   바뀝니다(하나의 실제 파일이므로). 영역 B 기준으로 이름을 바꾸면 영역 A에서 보이는 파일명도 달라집니다.
   필요하면 미리보기에 경고를 추가하겠습니다.
6. **자유 배치 → 자동 정렬 켬** 으로 바꾸면, 보이는 위치가 아니라 *순서 번호* 기준으로 정렬됩니다(사용자가 정한
   순서를 우선). 보이는 위치대로 하고 싶으면 먼저 "보이는 위치대로 순서 정하기"를 실행하세요.
7. 붙여넣기 위치: 대상 영역에 선택된 이미지가 있으면 **그 뒤에**, 없으면 끝에 넣습니다("새로 떠올린 컷을 중간에 끼워 넣기").

## 8. 데이터 손실 위험 (꼭 읽어 주세요)

**실제 파일을 바꾸는 기능은 네 가지뿐**입니다. 실제 파일명 변경(1장), 순서대로 일괄 변경, 실제 파일 이동, 실제 파일 삭제.
나머지는 전부 프로젝트 파일만 바꿉니다.

- **일괄 이름 변경**
  - 보호 장치: 미리보기, 충돌이 있으면 실행 불가(다른 파일을 덮어쓰지 않음), 임시 이름을 거치는 2단계 변경,
    실패하면 이미 바꾼 것을 되돌림, 로그 기록(`%LOCALAPPDATA%\ImageSceneOrganizer\rename_logs`)과
    *마지막 파일 이름 변경/이동 되돌리기*, 변경 직후 프로젝트 자동 저장.
  - 남은 위험: **이 파일을 참조하는 다른 프로젝트나 이전에 저장한 `.isregion` 파일은 옛 이름을 가리키게 되어
    "missing"으로 보입니다** → *누락된 이미지 다시 연결*로 다시 연결하세요. OneDrive 같은 동기화 폴더나 네트워크 드라이브,
    백신이 파일을 잡고 있으면 중간에 실패할 수 있습니다(롤백을 시도하지만 보장되지는 않음).
    되돌리기는 마지막 로그 1개 기준이고, 그 사이에 파일이 다시 바뀌었으면 일부를 건너뜁니다.
- **실제 파일 이동**: 대상 폴더에 같은 이름의 파일이 있으면 그 파일은 옮기지 않습니다. 다른 드라이브로 옮기면 복사 후
  원본 삭제 방식이라, 도중에 실패하면 대상 쪽에 일부 파일이 남을 수 있습니다(원본은 지우기 전에 실패하면 그대로 있음).
  이름 변경과 마찬가지로 다른 프로젝트·`.isregion` 파일은 옛 경로를 가리키게 됩니다 → 누락된 이미지 다시 연결.
- **실제 파일 삭제**: 확인 창을 거친 뒤 **휴지통으로 이동**합니다. 휴지통이 없는 드라이브(일부 네트워크/USB)는
  실패로 처리하고 파일을 건드리지 않습니다(영구 삭제로 넘어가지 않음).
- **프로젝트 파일에는 이미지가 들어 있지 않습니다**(경로만 저장). 이미지 폴더를 지우거나 옮기면 "missing"이 됩니다.
  다시 연결은 **파일 이름으로** 찾기 때문에, 다른 폴더에 같은 이름의 파일이 있으면 잘못 연결될 수 있습니다.
- **저장**: 임시 파일에 먼저 쓴 다음 교체합니다. 직전 버전은 `프로젝트.isproj.bak`으로 남습니다.
- **자동저장**: 별도의 복구 파일 1개에만 씁니다(원본 프로젝트는 덮어쓰지 않음). 비정상 종료 시 **최대 자동저장 간격(기본 3분)만큼의
  작업이 사라질 수 있습니다.** 프로그램을 **두 개 동시에** 실행하면 자동저장 파일을 함께 쓰고, 복구 질문이 잘못 뜰 수 있습니다.
- **Undo 기록은 메모리에만 있습니다.** 프로그램을 닫으면 사라집니다(최대 150단계).
- 잘라내기(Ctrl+X)는 붙여넣기 전까지 원본을 지우지 않습니다(흐리게 표시, Esc로 취소).
- 썸네일 캐시(`%LOCALAPPDATA%\ImageSceneOrganizer\thumbs`)는 계속 커집니다. 지워도 안전합니다.
